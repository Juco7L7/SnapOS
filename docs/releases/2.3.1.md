SnapOS for ARM64, package updates between releases, and an installer that can run on its own.

Two images in this release:

- `snapos-installer.iso` for x86_64 PCs (BIOS or UEFI).
- `snapos-installer-aarch64.iso` for ARM64 computers that boot by UEFI (ARM laptops, mini PCs and boards with a UEFI firmware). Same SnapOS; the system calls itself **SnapOS 2.3.1 ARM**. Boards that need a vendor image instead of UEFI (most Raspberry Pi setups) are not covered.

**One release for every computer.** `snapos update` downloads the release's source and builds the system for the computer it runs on, so both architectures update from this same release.

**The desktop and the programs update too.** At every login SnapOS also looks for newer packages on the NixOS 26.05 branch: the desktop (Budgie, Plasma, Xfce, Hyprland), the browser, the kernel and the rest, with their security fixes. `snapos update` installs them for the next start, and goes back by itself if the new system does not reach the login screen.

**Installing without questions.** A USB stick labelled `SNAPOS_ANSWERS` with a file `snapos-answers.env` (see the README) answers every question and the installer runs by itself.

**Verified by CI:** every desktop is booted in a virtual machine in both looks through the login screen; on ARM64 the image boots by UEFI in QEMU, SnapOS is installed unattended onto a virtual disk, and the installed system boots to the login screen.

Everything from 2.3 stays: choose Budgie, KDE Plasma, Xfce or Hyprland in the installer; `snapos update` with the pre-install checklist and automatic rollback; SnapGuard in real time; the Debian layer for `.deb` programs.

Flash with balenaEtcher. Checksums in the `.sha256` files.
